# Why this stage exists

Stage ID: `ROFL_FULL_SEMANTIC_DEEP_RECOVERY_V2`  
Owner: `ROFL_PARSER`  
Date: `2026-08-20`

## User value

The V1 baseline proved that every observed exact-build route can be preserved and
governed without pretending that explicit UNKNOWN is recovered gameplay truth. This
stage uses that inventory, runtime map, profiler, canonical schema, and paired anchors
to reduce the remaining high-value UNKNOWN/CANDIDATE/UNAVAILABLE surface through
actual reverse engineering. The target is evidence saturation, not a better-looking
coverage percentage.

## North Star value

Additional exact Replay semantics strengthen both precise offline features and the
calibration truth available to broader DETAILS/Timeline research. Parser ownership
remains limited to protocol facts. Map knowledge, behavioral inference, acquisition,
current-match orchestration, player profiles, and UI remain with their registered
owners.

## Scope

Primary work is exact build `16.16.805.0442`: Hero persistent state, damage stage and
attribution, Buff/Protection/Spell/Missile, entity taxonomy, Item/Economy, NPC and
world-object lifecycle, and high-value UNKNOWN/CLASSIFIED routes. V1 published
semantics are reused rather than re-researched. Legacy 16.15 is low-cost side evidence
only.

The stage adds an evidence-driven priority queue and semantic saturation report, then
executes the highest-information-gain hypotheses until current automated evidence is
exhausted or a real external input is required. Candidate rejection advances the
queue; it is not a stopping condition.

## Evidence and ownership boundary

Runtime names, layouts, frequency, correlations, and DETAILS alignment rank or bound
candidates but do not independently publish semantics. Missing values remain
unknown/null, never zero. The suspended `JUNGLE_OBJECTIVE_HOLDOUT_V1` is excluded from
all reads, enumeration, hashing, decoding, tests, and consumption. No network or
corpus acquisition, map truth, player behavior, Akari runtime/UI, or downstream
feature publication is introduced.

Realtime classification: `OFFLINE_RESEARCH_ONLY`, with future value for calibrated
`PRE_GAME_AVAILABLE` and `EARLY_GAME_AVAILABLE` consumers.
